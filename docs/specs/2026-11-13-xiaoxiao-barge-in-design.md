# 小小 v0.3.0：插話打斷設計

日期：2026-11-13。屬於 v0.3.0「對話更順」，接在顧問模式（`2026-11-12-xiaoxiao-work-advisor-design.md`）之後。

## 1. 意圖

使用者要解決的時刻（使用者選）：**顧問模式裡小小回答講太長，聽到一半想接話**。打斷之後要立刻聽使用者說，接著討論。

## 2. 目標／非目標／反目標

**目標**
- 顧問模式中，小小每唸完一句就留一個短空檔；使用者在空檔開口，就丟掉剩下的回答、改聽使用者說。
- 任何狀態下小小在說話時，按快捷鍵（或點角色）就立刻停下來。

**非目標**
- 句子講到一半就停（需要回音消除，這次不做）。
- 一般問答的空檔插話。一般問答只有一兩句；而且沒進顧問模式時，追問要先叫名字，在空檔聽到聲音不知道是不是旁人。（我的決定）
- 喊「小小」打斷。

**反目標**
- 旁人講話或環境雜音讓小小話講一半就停，剩下的回答也沒了。
- 句子之間的停頓讓小小說話明顯變慢、變得不自然。
- 一般問答、喚醒、追問的既有行為被改變。

## 3. 做法比較（使用者選了 D）

先做了拋棄式實驗（2026-11-13，Mac 喇叭音量 44，喚醒詞偵測照引擎的 AGC 跑）：

| 情境 | 喚醒命中 |
|---|---|
| 只播「嘿小小」 | 4/6 |
| 回答用正常音量，同時喊 | 0/6 |
| 回答音量 0.3，同時喊 | 1/4 |
| 回答音量 0.15，同時喊 | 2/4 |
| 只播回答 | 0 次誤觸 |

錄音也顯示：唸完一句後 0.1 秒內，麥克風音量就從 0.01～0.03 掉到 0.001～0.003，跟房間底噪差不多，句子之間的空檔是乾淨的。

- **A. 喊「小小」打斷**：回音把喚醒詞蓋掉，正常音量下 0/6，不成立。
- **B. 回音消除、一開口就停**：最自然，但整條收音路徑要重做（Mac 的 VoiceProcessingIO、Windows 的通訊模式），喚醒、小聲講話都要重測，工作量是 D 的好幾倍。
- **C. 只能按快捷鍵**：最便宜，但討論時要伸手按鍵，跟「想接話」的情境不合。
- **D. 句子之間的空檔插話，加上快捷鍵立刻停**（使用者選）：不需要回音消除；代價是要等那句唸完才插得進去，句子之間會多一點停頓。顧問回答每句 3～5 秒，最多等一句。

## 4. 行為

### 4.1 空檔插話（只在顧問模式）

1. 顧問回答照現在的做法串流，按句子切開，一句一句唸。
2. 每唸完一句、下一句還沒開始前，聽 **0.4 秒**（我的決定，依實驗的回音消散時間；builder 可在 0.3～0.5 秒之間調）。最後一句唸完後照舊開顧問窗口，不另外留空檔。
3. 空檔內偵測到開口（用既有的說話偵測），就**先暫停、不唸下一句**，繼續收音。
   - 跟顧問窗口一樣，要連續講約 0.3 秒才算開口（`ONSET_BLOCKS`），一聲雜音不算。
   - 如果只是一聲雜音，沒有連續講到 0.3 秒，就接著唸下一句。暫停最多多出約 0.3 秒。
4. 確認是有人開口：剩下的句子不唸了。收音照顧問模式的斷句規則（停頓 1.5 秒、最長 30 秒），講完轉文字，當成下一輪送出。
5. **插話內容不成立時要接著唸**（防反目標）：如果轉出空字串、垃圾字串，或 sonnet 回 `<<SKIP>>`，就把剛才沒唸的句子接著唸完。為了做到這一點，被丟棄的句子要先留著，不能直接丟掉。（我的決定）
6. **給 sonnet 的記錄**：討論文字（`Transcript`）只記實際唸出來的部分，並在後面標「（被使用者打斷）」。sonnet 常駐程序自己的對話記錄有完整回答，`Transcript` 只在程序重開時才送，所以插話那一輪送出的訊息前面要再加一行註記，寫明上一則只唸到哪裡、使用者沒聽到後面。摘要也只能根據使用者實際聽到的內容。（我的決定，builder check 後補）
7. 被打斷時，claude 可能還在產生剩下的回答。剩下的就不再唸，等它產生完或直接結束這次請求，由 builder 決定；不能讓舊回答的句子在新一輪裡被唸出來。

### 4.2 快捷鍵立刻停（所有狀態）

- 小小在說話時（任何 `Speaking`，包含一般回答、摘要、「我在」），按快捷鍵或點角色，就立刻停止說話。
  - 一般問答：停下來後直接開始聽（像叫醒後的 `Listening`，但不再唸「我在」，只叮一聲）。（我的決定）
  - 顧問模式：停下來後開顧問窗口，不用叫名字。
  - 唸「要存重點嗎」或摘要時被停：直接開存檔確認窗口。
  - 其他說話被停：進入「原本唸完就會進的狀態」。確認對話的問句被停→`Confirming`，回答類→`Listening`。原本唸完就回待命的（提醒或計時到點、錯誤訊息、「提醒設好了」這類完成回報）只停聲，回到原狀態、不開始聽；休息中唸的提醒被停，就維持休息。「我查一下」被停，連同後面的查資料一起取消。（我的決定，builder check 後補）
  - 顧問回答被快捷鍵停下，不像空檔插話那樣在沒講話時接著唸；剩下的直接丟掉，但跟 4.1 第 6 點一樣標記打斷、下一則訊息加註記。快捷鍵是使用者主動按的，不需要防雜音。（我的決定，builder check 後補）
- 不在說話時，快捷鍵行為不變。

### 4.3 不變的部分

一般問答的追問（8 秒、3 輪、要叫名字）、喚醒、確認對話、休息都不變。一般問答不留句間空檔。

## 5. 技術約束

- **說話要能從別的執行緒停掉**：`Speaker` 加 `stop()`，可以在快捷鍵的執行緒呼叫。Mac 停掉 `say` 程序；Windows 停掉 SAPI 的播放。`say()` 被停掉時要能回報「被打斷」，跟正常唸完分得出來。
- **空檔要能讀麥克風**：句子是在 `sess.ask` 的串流回呼裡唸的，空檔收音也要在這裡做，或改成先把句子放進佇列、由主迴圈唸跟聽。由 builder 決定，但不能讓 claude 的串流因此卡住或逾時。
- **唸完要丟掉回音**：既有的 `after_speaking`（flush）仍要做；空檔是在 flush 之後才開始聽。
- Mac 與 Windows 都要做，Windows 至少要能編譯並通過 CI；Windows 實機另外找時間測。

## 6. 隱私

不變：插話跟一般顧問輪一樣，只送轉出來的文字；紀錄檔記事件（例如 `barge_in`、有沒有接著唸），不記內容。

## 7. 驗收

- **自動測試**（fake 音訊與 fake speaker）：
  - 顧問回答第一句後的空檔有人開口：第二句以後不唸，下一則送給 sonnet 的是插話內容，`Transcript` 有「被使用者打斷」標記。
  - 空檔只有一聲雜音：照樣唸完全部句子。
  - 插話轉出垃圾或 `<<SKIP>>`：接著唸剩下的句子。
  - 說話中按快捷鍵：說話被停、進入對應的收音狀態（一般問答是 `Listening`，顧問模式是顧問窗口）。
  - 一般問答不留空檔、行為不變（既有測試全過）。
- **實機**（Mac，先用喇叭和 `say` 自測，再請使用者實測）：
  - 顧問回答第二句開始前的空檔插話，能接著討論。
  - 背景有一點雜音時，回答不會被切斷。
  - 句子之間的停頓聽起來可以接受（請使用者判斷）。
  - 快捷鍵在一般回答和顧問回答中都能立刻停下來。
- **手冊**：`docs/manual.md` 補怎麼插話；`docs/feature.md` 更新狀態。

## 8. 留給 builder（builder check 確認可自行決定）

空檔確切長度（0.3～0.5 秒）、空檔收音放在串流回呼還是主迴圈、被打斷後 claude 請求怎麼收尾、`stop()` 在兩個平台的實作方式、紀錄事件的欄位名稱。
