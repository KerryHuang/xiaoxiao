# 日常語音助理「小小」App 設計

日期：2026-11-05　狀態：已過 builder check，待使用者核准
前置：會議版小小（作者另一個專案，已上線並完成首場試用）
實驗證據：作者本機的丟棄式實驗腳本（延遲、喚醒、複核、查資料、分流、確認對話、麥克風使用偵測），結果整理在 §3

## 1. 意圖

使用者想要一個像百度「小度」的 AI 助理：平常就在，說「嘿，小小」就出現，問你需要什麼，然後幫你解答或幫你做事。
和小度的差別在於它**懂使用者的工作脈絡**（規格、程式、票、資料庫、筆記），不是智慧音箱。

這是**個人工具**：第一批使用者是作者自己和熟人，之後可能公開發給其他人。

成功的樣子：在 Mac 或 Windows 上裝好 app，登入官方 Claude 一次。之後不開任何視窗，說「嘿，小小，一公斤幾公克」，
大約 2 秒就從喇叭聽到答案；說「嘿，小小，提醒我三點開會」，它會先複述一次，你說「對」它才建立提醒，做完會告訴你。

## 2. 目標／非目標／反目標

**目標**
- 開機自動待命，三種觸發方式：喚醒詞「嘿，小小」、全域快捷鍵、點選單列（或系統匣）圖示。
- 四種用途都要支援：工作查詢、生活雜事、幫我做事、聊天發想（可以連續追問，不必每句都喊喚醒詞）。
- Mac 和 Windows 都能用，用同一份程式碼出兩個平台的版本。
- 用使用者自己的 Claude 訂閱（見 §6 授權）。
- 喚醒、聽寫、說話全部在本機完成；沒叫它時 0 token。

**非目標（第一版）**
- 上架 Mac App Store 或 Microsoft Store。
- 行動裝置、智慧音箱、跨裝置同步。
- 自然語音（第一版用作業系統內建語音）。
- 多人或多帳號、團隊共用設定。
- 取代會議版小小（開會時由會議版負責，日常版會自動暫停）。

**反目標**（能跑但算失敗）
- app 自己提供「登入 Claude」，或讀取、保存 Claude 的 token（違反 Anthropic 條款，見 §6）。
- 喚醒前的聲音被存檔或送出本機。
- 沒有經過使用者確認就寫入任何東西（提醒、筆記、票、信）。
- 寫入失敗卻沒有說出來。
- 通話中搶話、或回答被收進會議裡。
- 整天收音讓藍牙耳機一直維持在通話音質。
- 待命時明顯耗電，或常駐佔用好幾 GB 記憶體。

## 3. 已實測的事實（2026-11-05，Mac）

| 項目 | 結果 |
|---|---|
| `claude -p` 啟動（帶 `--setting-sources user --strict-mcp-config`） | 0.3 秒；慢的是 API |
| haiku 常駐程序（stream-json 輸入輸出）首字 | 0.85～1.2 秒，穩定 |
| 喚醒第一關 sherpa-onnx KWS，`zh-en-3M-2025-12-20` 模型，關鍵詞 `h ēi x iǎo x iǎo` | 80 分鐘真人會議錄音（不公開）：喚醒 2/2，誤觸 1 次（「可以再思考」）；CPU 約一顆核心 0.8% |
| 舊模型 `wenetspeech-3.3M-2024-01-01` | 1/2，不穩，不採用 |
| 第二關 Whisper 複核，取命中點往前 3.5 秒 | small 與 turbo 都 2/2，並擋下那次誤觸；取 2.5 秒會漏掉。small 0.9 GB、0.13～0.6 秒；base 不準 |
| 音檔冒煙測試，整條流程 | 問題講完到第一句開口 1.4～2.3 秒 |
| 查資料題 | 網路 21～25 秒（每次 WebSearch 約 10 秒），本地 docs 9～13 秒 |
| 合併分流（能答直接答，否則輸出標記） | 16/16 |
| 做事前確認對話 | 3 段可行，每輪 1.4～3.6 秒；發現要補的規則見 §5.4 |
| 每題 token | haiku 快答約 1.6 萬（幾乎都命中快取，折合 0.0002 美元）；sonnet 查資料約 4 萬（0.07 美元） |
| launchd 啟動的程序收麥克風 | 可以 |
| CoreAudio 列出正在用麥克風的程序 | 可以（macOS 14.2+） |
| 藍牙耳機麥克風一打開 | 耳機輸出從 44.1 kHz 掉到 16 kHz |
| Claude Desktop 內建的 Claude Code CLI | 存在，可以用 `-p` 回答 |

**未驗證**：使用者本人聲音直接對麥克風的喚醒命中率與日常誤觸率（決定放到最後一起測）；Windows 上的一切；
Teams 真正通話中會不會出現在麥克風使用清單；換一台 Mac 第一次執行時的權限授權；只登入 Desktop 的人能不能用內建 CLI；
改用 `--system-prompt` 能省多少 token；待命時的電池消耗。

## 4. 架構

```
小小 app（Tauri：一份程式碼出 Mac／Windows 版）
 ├ 外殼：選單列／系統匣圖示、設定視窗、第一次啟動引導、全域快捷鍵、開機啟動、自動更新
 └ 引擎（背景執行）
    ├ 收音：系統預設輸入（不用藍牙耳機的麥克風，§7）
    ├ 喚醒：sherpa-onnx KWS 常駐 → 命中後 whisper-small 複核往前 3.5 秒
    ├ 聽寫：Whisper 轉問題
    ├ 分流：本機固定指令 → 否則交回答引擎
    ├ 回答引擎：Claude（§6）；haiku 常駐程序快答，需要時轉慢路線
    ├ 說話：作業系統內建語音（Mac 美佳；Windows 台灣國語語音）
    └ 暫停偵測：其他程序在用麥克風、鎖定螢幕、睡眠
```

**引擎用 Rust 寫（使用者決定）**，和 Tauri 同語言：喚醒直接呼叫 sherpa-onnx 的 C API，聽寫用 whisper.cpp（Mac 用 Metal 加速），
不內嵌 Python。理由是安裝包小、簽章與公證容易、Mac 和 Windows 共用同一套邏輯。
喚醒與複核的行為要和 §3 實測的設定一致（模型、關鍵詞、門檻、3.5 秒窗口）；實驗用的 Python 腳本只當參考，不沿用。
會議版小小不必和它共用程式碼；共用的是設計與參數。

## 5. 互動流程

### 5.1 喚醒

1. 第一關命中 → 收 0.4 秒尾音 → whisper-small 複核往前 3.5 秒的錄音，比對 `(嘿|黑|hey|嗨|欸|誒|可以)?…小小`（容錯，沿用會議版的經驗）。
2. 通過 → 叮一聲＋說「我在」→ 開始錄問題。不通過 → 什麼都不做，只記一筆事件。
3. 快捷鍵與點圖示跳過這兩關，直接叮＋「我在」。

### 5.2 錄問題

偵測到停頓 0.8 秒就算講完，最長 10 秒；6 秒內沒開口就放棄。音量門檻要用自動增益後的訊號，不要寫死絕對音量（實作補充：增益會把環境音一起放大，所以「有人講話」還要比環境雜訊底高約 10 dB；追問窗口要連續講 0.3 秒才算開口，不喊喚醒詞最多連續追問 3 輪）
（USB 麥克風實測比會議錄音小約 25 dB，寫死門檻會失靈）。

### 5.3 回答與分流

1. **本機固定指令**（0 token）：現在幾點、今天幾號、計時 N 分鐘、取消計時、小小先休息。可以直接做的就直接做並說結果。
   「提醒我三點開會」屬於寫入，走 §5.4。
2. 其他交給 haiku 常駐程序，它能答就直接答（第一句一產生就開始說）；
   需要查資料就只輸出 `<<LOOKUP>>`，要做事就只輸出 `<<ACTION>>`。
3. `<<LOOKUP>>`：先說「我查一下」，交給慢路線（sonnet＋唯讀工具：Read、Grep、Glob、WebSearch）。超過 30 秒就說「查不到，晚點再問我」。
   **查詢範圍**：預設只開網路搜尋，不開任何本機資料夾；使用者在設定裡逐一加入資料夾才可讀。一律排除 `.env*`、`.ssh/`、`*.pem`、`*.key`、`id_*`、Keychain 與瀏覽器設定檔，因為讀到的內容會送到雲端。
4. 提示詞要寫成語音口吻：不用條列和符號，一次一兩句；**不可以把分類說出口**（實驗中出現過「這是討論發想類……」）。

### 5.4 幫我做事（使用者決定：先確認需求再做）

1. 用一句話複述理解；缺了**必填**資訊才問，而且一次只問一件事。
2. 小小講完後 8 秒內聽到的話，直接當作回覆，不用再喊喚醒詞。
3. 使用者說「對／好」→ 照目前的內容做；選填資訊沒給就不再追問（實驗第三段卡在這裡）。說「不對，……」→ 修正後再複述一次。說「取消」→ 放棄。
4. 做完用語音回報結果（例如「提醒設好了，三點」）；失敗要說出原因。
5. 第一版支援的動作與欄位：

   | 動作 | 必填 | 選填 |
   |---|---|---|
   | 提醒 | 時間、內容 | 重複 |
   | 計時 | 長度 | 名稱 |
   | 筆記 | 內容 | 標題 |

   開票、寄信這類動作，要等設計好工具白名單後再加。
6. **時間由 LLM 解析成結構化欄位**，提示詞帶入目前的本地時間與時區（取系統時區）。確認時輸出一行 `<<DO>>` 加上 JSON，例如 `{"type":"reminder","at":"2026-11-05T15:00:00+08:00","text":"開會"}`；本機程式驗證欄位齊全、時間在未來才執行。
   「三點」這類沒講上下午的說法：取接下來最近、落在 07:00～22:00 之間的那個時間；兩個都不在這個範圍內就問。複述時一律講出「下午三點」這種完整說法，讓使用者有機會更正。

### 5.5 聊天發想

回答後 8 秒內還能直接追問。常駐程序會累積上下文：**閒置 5 分鐘就開新對話**（數字是 builder 的預設，可調）。

## 6. 授權與回答引擎（使用者決定：先 A，公開發布時加 B）

Anthropic 2026-02 起明文規定：訂閱方案的 OAuth 只能用在 Claude Code 和 Claude.ai；第三方產品不得提供 claude.ai 登入，
也不得用訂閱額度送出請求，應改用 API key（媒體報導，條款原文尚未讀）。

- **A（第一版）**：app 呼叫使用者自己裝、自己 `/login` 的官方 Claude Code CLI。先找 PATH 上的 `claude`，
  找不到再動態尋找 Claude Desktop 內建的那份（路徑帶版本與 hash，每次啟動重新找，不寫死）。
  都沒有，或尚未登入 → 引導使用者到 Claude Code／Desktop 自己登入。app **不碰** token。
  這是灰色地帶，自用與熟人使用時風險低；公開發布前要重新評估。
- **B（公開發布時）**：設定裡填 API key，直接呼叫 Claude API；工具要自己實作。第一版只在設定的資料結構裡預留這個選項，不實作。
- 引擎留設定欄位，以後可以換 codex、agy 或本機模型（都還沒驗證）。
- 呼叫 CLI 時一律鎖住權限：`--tools` 只放白名單、`--setting-sources user`、`--strict-mcp-config`、`--permission-mode dontAsk`
  （沿用會議版：不這樣做會繼承專案裡預先允許的寫入權限）。

## 7. 隱私與常駐規則

- 喚醒前的聲音只放在記憶體（最近 3.5 秒，不斷覆蓋），不落檔、不外送。
- 送到雲端的只有問題的文字，音檔不存、不送。
- 紀錄檔只記事件（時間、延遲、是否通過複核），不記內容。診斷模式（記錄每段話的轉錄）要手動開，並在設定裡顯示警告。
- **任何其他程序在用麥克風時就暫停**（同時涵蓋通話與會議版小小），暫停時放開麥克風，每 2 秒檢查一次，恢復後繼續（使用者決定）。通話結束後最多 2 秒的空窗可以接受。
  Mac 用 CoreAudio 的 process object（`prs#`、`piri`、`ppid`，已驗證）；Windows 的方法待驗證。
  **備案**：某個平台或會議軟體偵測不到時，該平台改成通話中只保留快捷鍵觸發、喚醒詞關閉，並在設定頁標明「此平台無法自動偵測通話」。
- 鎖定螢幕、睡眠時暫停。
- 預設輸入如果是藍牙耳機，**不要拿它收音**：改用內建或 USB 麥克風，並在引導畫面說明原因；耳機只負責播放。
- 系統的麥克風使用指示（Mac 的橘點）不隱藏。
- 選單列可一鍵靜音；說「小小，先休息」也可以暫停。

## 8. 安裝與第一次啟動

- Mac：`.dmg`；Windows：安裝程式。從 GitHub Releases 下載，不上商店。
- 引導步驟：麥克風權限 → 選收音麥克風（附即時音量條；會擋下藍牙耳機和全靜音的裝置）→ 下載或確認中文語音 →
  偵測 Claude Code 是否已登入 → 喊一次「嘿，小小」試試看。
- 模型（KWS 約 3MB、whisper-small）在第一次啟動時下載，或隨安裝包附上，由 builder 決定。

## 9. 發布與費用

- 自用與熟人：可以不簽章，教使用者略過系統警告。
- 公開發布：Apple Developer ID 簽章與公證（每年 99 美元）；Windows 程式碼簽章（每年約 100～400 美元，未查證）。
- 回答走 A 時用訂閱額度，不另外收費。

## 10. Repo 與關係（使用者決定）

- 新開**個人公開 repo** 放 app 與引擎；公開 repo 不得出現公司名稱、客戶名稱、內網位址、個人路徑。
- plugharbor toolkit 只放一個「安裝與控制小小」的 skill（可選，之後再做）。
- 會議版小小維持原樣，兩者不互相依賴。

## 11. 交付順序與驗收

1. Mac 版 app（含外殼、引擎、三種觸發、固定指令、快答與慢路線、做事確認、暫停偵測）。
2. Windows 版：說話引擎、暫停偵測、開機啟動；在使用者的 Windows 機器上建置與測試。
3. **最後一起做語音實測**（使用者決定）：
   - 本人聲音直接對麥克風喊 20 次「嘿，小小」，命中至少 18 次（門檻是 builder 的提議）。
   - 日常工作 30 分鐘以上，誤觸最多 1 次。
   - 問題講完到第一句開口，快答不超過 3 秒。
   - 兩個平台各測一次。
4. 每個階段的自動測試：喚醒與複核用 §3 的錄音片段和合成語音當回歸測試資料（不提交真人錄音進公開 repo）；
   分流、確認對話用固定問句集測。

## 12. 失敗與降級（builder check 後補）

- 回答引擎不可用（Claude Code 沒裝、沒登入、更新中、額度用完、逾時）：常駐程序自動重啟一次；仍失敗就退回只做本機固定指令，用語音說「現在連不上 Claude，我只能報時和計時」，選單列圖示顯示警告，並附上「去登入」的按鈕。每 5 分鐘重試一次。
- 本機固定指令永遠可用，不依賴網路或 Claude。

## 13. 平台與發布（builder check 後補）

- Mac 與 Windows 都是硬性交付。跨平台抽象層從第一天就定好：收音、麥克風使用偵測、說話、開機啟動、通知。
- Windows 上驗證失敗的功能可以降級上線（例如 §7 的備案），但要在設定頁標明；不可以靜默缺功能。
- 第一版不做自動更新，從 GitHub Releases 手動下載；自動更新與簽章一起放到公開發布階段。
- 回歸測試資料用合成語音（Mac `say`、Windows 內建語音）產生並提交；真人錄音只放本機、不進 repo。
- 模型授權：sherpa-onnx KWS 模型是 Apache-2.0，Whisper 是 MIT，都可以隨安裝包附上（附上授權檔）。

## 14. 留給 builder 決定

- Windows 偵測麥克風使用的方法與文字轉語音 API 的選擇。
- 模型隨安裝包附上，或第一次啟動時下載。
- 閒置清空上下文的秒數、追問窗口的秒數（預設 5 分鐘、8 秒）。
