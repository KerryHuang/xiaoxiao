# 小小桌面小角色與休息模式（v0.2.0）設計

## 為什麼做

現在小小的存在感只有選單列或系統匣的一個小圖示：看不太出來它有沒有在聽，要開口也要記快捷鍵。設定完之後，使用者希望打開小小就看到一個小角色待在桌面上：看它就知道狀態、點它就能說話、不想被打擾就讓它休息。

使用者也要能明確讓小小「不工作、不收音」。這件事關乎信任，所以休息時麥克風必須真的關閉，而且看得出來。

參考對象是 ChatGPT 的浮動小視窗（可拖曳的小角色、右鍵選單）。**只參考操作方式，造型必須原創，不使用 ChatGPT 的角色或素材。**

## 目標

- 設定完成後，打開小小只出現小角色，不開主視窗。
- 小角色用表情和動作顯示狀態，點一下就能說話，右鍵叫出選單。
- 提供八個原創造型，使用者可換，預設「小訊」。
- 一個明確的「休息」：關麥克風、不聽、不回答，叫醒後馬上能用。
- Mac 與 Windows 行為一致。

## 不做

- 不做打字輸入、文字回答或對話紀錄。小小仍是語音助理。
- 不做開機自動啟動（v0.2.0 已決定預設不啟動，也沒有開關）。
- 不把通話偵測改成螢幕分享偵測，也不嘗試從分享畫面排除視窗。
- 不提供第三方或自訂造型。

## 不能發生的事

- 休息中麥克風還開著。
- 角色顯示休息或暫停，實際上還在聽（反過來亦然）。
- 隱藏角色後使用者找不到設定或結束的入口。
- 通話或開會時，角色還留在畫面上被分享出去（在偵測得到通話的情況下）。

## 使用者決定的事

| 主題 | 決定 |
|---|---|
| 角色用途 | 顯示狀態＋點一下說話＋右鍵選單。可拖曳 |
| 造型 | 八個（小麥、小圓、小鴞、小訊、小雲、小喵、小芽、小企），使用者可換，**預設小訊** |
| 隱藏 | 保留選單列／系統匣圖示；選單可叫回角色；隱藏時小小繼續待命 |
| 通話或開會 | 角色自動收起，結束後自動出現（沿用現有通話偵測） |
| 休息 | 關麥克風、不聽不回答；模型留在記憶體，叫醒立即可用；計時照響 |
| 版本 | 併入 v0.2.0 一起發佈（在獨立分支開發，測過再合回 `windows`） |

已知的取捨：只分享螢幕、沒有開麥克風時偵測不到通話，角色會留在畫面上，使用者要手動隱藏。

## 行為

### 打開與關閉

- 還沒完成引導（`onboarded` 為 false，含模型還沒下載好）：照現在一樣打開引導視窗，引擎不啟動，不顯示角色。按「開始待命」後主視窗關閉、角色出現。
- 已完成引導：打開小小只出現角色。再次打開 app（已在執行時）若角色被隱藏就叫回；不開設定視窗。
- 重新走引導期間不顯示角色。

### 角色狀態

對應引擎現有狀態：

| 引擎狀態 | 角色表現 |
|---|---|
| Idle | 待命（偶爾眨眼） |
| Acking、Listening、FollowUp、Confirming | 聆聽 |
| Thinking | 思考 |
| Speaking | 說話 |
| Paused（休息） | 暫停（閉眼、z） |
| NoMic、Degraded | 待命造型加明顯的警告標記；滑過時顯示原因 |

通話時角色已收起，鎖定時畫面看不到，所以實際看得到的暫停只有休息，一種造型就夠。

使用者偏好減少動態時，動畫要關閉，但狀態仍要看得出來。

### 操作

- 左鍵點一下：等於按快捷鍵（`Trigger`）。休息中則是叫醒。
- 拖曳：移動角色，位置要記住；下次打開在同一處。螢幕變動導致位置跑出畫面時要移回可見範圍。
- 右鍵選單：休息／叫醒、設定…、隱藏、結束小小。
- 選單列／系統匣選單：現有項目加上「顯示小角色」／「隱藏小角色」；「靜音」改為「休息」／「叫醒」。

### 休息

把現在的「靜音」和語音指令「小小，先休息」合併成同一個休息狀態，避免兩個名字、兩種叫醒方式。

- 進入：右鍵選單、選單列／系統匣、或說「小小，先休息」。
- 叫醒：點角色、按快捷鍵、右鍵或選單列的「叫醒」。
- 不再自動醒來；重開小小後回到待命（休息不跨啟動保留）。
- 程式現況：兩者都已會關麥克風（`pipeline.rs` `check_pause`），計時在暫停時也會響（`fire_due`）。差別只在 `muted` 不能用 `trigger` 解除。
- 統一方式：拿掉 `muted`，只留 `resting` 一個旗標，「靜音」相關介面一併改成休息。
- 休息中遇到通話或鎖定：維持現有規則（`on_trigger` 清掉休息，但還有其他暫停理由就先不開麥克風，等理由結束才恢復）。

### 通話與鎖定

- 偵測到其他程式使用麥克風：角色收起，引擎照現有規則暫停；結束後角色回來。
- 鎖定螢幕：照現有規則暫停，角色不需要特別處理。
- 使用者手動隱藏時，通話結束不應該把它叫回來。
- 引擎只有一個 `Paused` 狀態，外殼分不出原因。引擎要新增「暫停原因」（休息、通話、鎖定）通知外殼，可以改引擎的公開介面，並補單元測試。

### 造型與設定頁

- 設定頁新增「小角色造型」：平常收在抽屜裡只顯示目前的角色，打開才看到八個選項附預覽，選了立即生效。
- 八個造型的五種狀態以 SVG 繪製；草圖見 brainstorming 階段，定稿時精修。名稱暫定小麥、小圓、小鴞、小訊。

## 限制

- 公開 repo：不放公司或客戶名稱、個人路徑；素材需原創。
- 隱私規則不變：聲音不存檔、不上傳；紀錄不含內容。
- 角色要低耗能：待命時不能為了動畫明顯增加 CPU。Windows 機器算力已偏緊。
- 不改變語音流程與 Claude 權限設定。

## 我代為決定的事（請確認）

審查時補上的設計判斷，使用者可以推翻：

- 暫停原因由引擎通知外殼；`muted` 併入 `resting`。
- `Confirming`、`FollowUp` 都算聆聽。
- 暫停只有一種造型。
- CPU 增加上限 1 個百分點。
- 引導或模型未完成時不顯示角色。
- 休息不跨啟動保留，重開回到待命。

## 交給實作者決定

- 視窗實作方式（透明、無邊框、最上層、不出現在工作列／Dock 的 Tauri 視窗；Mac 透明視窗需要的設定）。
- 角色尺寸（建議約 96 px）與高 DPI 處理。
- 全螢幕 app 時的顯示行為：跟隨系統預設，不特別處理。
- 動畫做法與精修細節。
- 新增設定的欄位名稱，以及舊設定檔的相容（缺欄位就用預設值）。

## 怎麼算完成

Mac 與 Windows 各實測一次：

1. 乾淨安裝走完引導，角色出現；重開只看到角色。
2. 五種狀態與實際行為一致；休息時系統麥克風指示確實熄滅。
3. 點一下能說話；休息中點一下能叫醒；快捷鍵行為相同。
4. 拖曳後重開位置不變；拔掉外接螢幕後角色仍在可見範圍。
5. 隱藏後從選單叫回；手動隱藏時通話結束不會自己回來。
6. 通話開始角色收起、結束回來。
7. 換造型立即生效，重開仍保留。
8. 待命時整機 CPU 比沒有角色的版本增加不超過 1 個百分點（數字記入驗收紀錄）。超過就把待命動畫改成靜態，只在其他狀態播放。
